# 视觉 V3：轻量网页路线研究

日期：2026-09-22
执行器：ChatGPT-AgentDock
Active roles：Visual Researcher / Art Director / Technical Artist / QA & Performance

## 1. 本轮目标

重新判断本项目应该采用什么视觉路线。目标不是复刻某款商业游戏，而是提取“豆芝麻海豹”类掌上养成作品和 HD-2D 的有效视觉原则，形成原创、可爱、具有空间感，同时适合静态网页和移动端加载的方案。

本轮不修改正式游戏业务代码，不迁移 V2 3D，不制作大体量美术资产。

## 2. 可验证事实

### 2.1 豆芝麻海豹并不是单纯的 2D 像素游戏

任天堂对 2009 年 DS《クプ～！！まめゴマ！》的官方介绍明确写到：玩家可以在“3D 空间”里与两只まめゴマ自由玩耍。也就是说，用户此前感觉它带有 3D / 3D 转 2D 的空间感并非错觉。

2012 年 3DS《まめゴマ よいこ まるいこ げんきなこ！》官方商品页又明确说明该作是 Nintendo 3DS 专用，并支持 3DS 的立体 3D 显示；公开截图则是 2D 截图形式。

公开画面能观察到的稳定视觉特征：

- 角色轮廓极圆、极简单，五官面积小但识别度高。
- 场景采用固定或接近固定的斜俯视视角，不追求自由镜头。
- 地面、树、玩具和装饰采用大色块、低细节和玩具箱式构图。
- 角色与场景都以柔和明亮的色彩为主，没有写实材质负担。
- “可爱感”主要来自比例、轮廓、表情、动作和场景关系，而不是模型面数或高分辨率纹理。

当前没有找到可信的一手资料公开其具体游戏引擎、材质管线、模型面数或是否使用预渲染，因此不能把这些细节写成事实。

主要来源：
- Nintendo DS 官方页：https://www.nintendo.co.jp/ds/software/b53j/index.html
- Nippon Columbia 3DS 商品页：https://columbia.jp/prod-info/CTR-P-AM6J-JPN/
- 4Gamer 3DS 截图库：https://www.4gamer.net/games/147/G014714/screenshot.html
- Famitsu 3DS 公开画面：https://www.famitsu.com/news/201202/01009272.html

### 2.2 《歧路旅人》的 HD-2D 不适合原样照搬到轻量网页

Square Enix / Acquire 的公开访谈说明：Octopath Traveler 的核心是把 2D 像素角色放在丰富的 3D 环境中；Octopath Traveler II 的背景“几乎全部是 3D”，并使用动态昼夜光照和更强的 3D 摄像机表现。

这意味着真正的 HD-2D 并不是“几张 2D 图叠起来”，而是一套偏 3D 游戏制作的管线。它值得借鉴的是：

- 固定或受控镜头；
- 2D 角色与空间深度共存；
- 前景 / 中景 / 背景的层次；
- 局部景深；
- 光影和色调让低分辨率素材显得更“富”；
- 角色保持清晰、背景承担空间感。

不值得当前项目直接照搬的是：

- 大量运行时 3D 几何；
- 重型实时材质；
- Unreal 类完整 3D 渲染栈；
- 自由旋转摄像机。

主要来源：
- 4Gamer Octopath 开发访谈：https://www.4gamer.net/games/368/G036845/20180615177/
- Unreal Engine / Acquire Octopath Traveler II 访谈：https://www.unrealengine.com/developer-interviews/octopath-traveler-ii-builds-a-bigger-bolder-world-in-its-stunning-hd-2d-style

## 3. 当前网页基线体量

2026-09-22 本机实测正式 2D 入口核心文件：

| 文件 | 大小 |
| --- | ---: |
| `dist/index.html` | 6.1 KB |
| `dist/style.css` | 11.2 KB |
| `dist/app.js` | 22.5 KB |
| `dist/engine.js` | 15.9 KB |
| `dist/assets/hamster-atlas.webp` | 530.4 KB |
| `dist/assets/room.webp` | 504.9 KB |
| `dist/assets/wheel.webp` | 160.8 KB |

`dist/assets/` 合计约 1,224,852 bytes。也就是说，当前正式版的主要体量本来就不是 JavaScript，而是美术资源。

这对 V3 很重要：不需要为了“像游戏”先引入大框架。当前状态机和 Canvas 结构足够支撑一个 2D/2.5D 小原型。

Phaser 4 官方 README 给出的完整 minified 包约 1.29 MB raw / 345 KB gzip。它本身并不算巨大，但对于本项目“首屏约 1.5 MB”的目标，额外 345 KB gzip 仍是一笔明显成本，而且不会自动解决美术质量。因此 V3 原型阶段优先不新增 Phaser。

来源：https://github.com/phaserjs/phaser/blob/master/README.md

## 4. 四条候选路线比较

### 路线 A：继续真实运行时 3D（Three.js + GLB）

优点：
- 真正有空间、遮挡、光照和连续旋转能力。
- 动作可以由骨骼驱动。

问题：
- 当前 V2 已验证：技术可行不等于好看。
- 模型、贴图、动画和运行库会持续占体量。
- 要达到豆芝麻海豹那种“统一可爱”的效果，需要原创角色建模、场景建模、材质、灯光一起重做，成本远高于现在。
- 手机 GPU / 首屏加载成本最高。

结论：不作为 V3 主路线。保留现有 V2 作为技术实验和交互参考。

### 路线 B：真正的 HD-2D（2D角色 + 运行时3D背景）

优点：
- 空间感和光照表现上限高。
- 可以接近《歧路旅人》式现代像素视觉。

问题：
- 仍然需要 3D 背景资产、相机和 WebGL 管线。
- 当前项目只有单房间养成场景，没有必要为镜头自由度付出完整 3D 成本。
- 比用户真正需要的“可爱、温馨、轻量”更复杂。

结论：只借视觉原则，不借完整技术栈。

### 路线 C：预渲染 2.5D 玩具屋（推荐）

定义：场景和家具可以先在 3D 软件或绘图工具中做出统一视角，再烘焙为 WebP/AVIF 图层；浏览器运行时只处理 2D sprite、层级、阴影、遮挡和少量粒子。

优点：
- 可以得到“像 3D”的圆润体积感，但网页不加载 GLB、Three.js 或实时材质。
- 固定视角非常适合养成房间。
- 能把美术质量集中在少数画面，而不是做一整套自由 3D 世界。
- 场景可拆成前景 / 中景 / 背景 / 可互动物件，保留遮挡和层次。
- 体量可预测，可通过 WebP、图集合并和懒加载严格控制。

问题：
- 相机基本不能自由旋转。
- 家具如果要大范围自由摆放，需要准备统一透视的独立 sprite。

结论：最适合本项目。

### 路线 D：纯 2D 像素 + 分层伪 3D

优点：
- 最轻、最稳定、最容易兼容浏览器。
- 现有 Canvas 代码可直接利用。

问题：
- 如果只是普通像素房间，会再次变成“平面纸片感”。
- 必须额外做接触阴影、遮挡、Y-sort、前后景、微光和动作体积感，否则达不到用户想要的空间感。

结论：可作为路线 C 的运行时基础，而不是独立采用“纯平面像素风”。

## 5. V3 推荐方向：Soft Pixel Diorama / 软像素玩具屋

这不是严格复刻《歧路旅人》，也不是继续做真实 3D。

目标观感：

> 豆芝麻海豹式圆润玩具感 + 掌机低分辨率亲和力 + HD-2D 的层次/光影原则 + 网页 2D 的轻体量。

### 5.1 角色

- 原创仓鼠继续作为视觉绝对主体。
- 使用 2D sprite，不使用运行时 3D 模型。
- 轮廓强调“球、团、软”：大身体、短四肢、极简五官、较大的脸部留白。
- 不做粗黑像素描边；改成深色软轮廓 + 局部高光，让它既像像素角色又有玩具体积。
- 采用 4 方向或“正面 / 背面 / 侧面（左右镜像）”即可，不制作 8 方向。
- 动画以低帧数 sprite + 少量程序形变组合：例如 4~6 帧走路，再叠加 bob / squash / shadow stretch，而不是每个动作几十帧。

### 5.2 场景

- 固定 3/4 斜俯视，不开放用户旋转镜头。
- 房间拆为 4~6 个深度层：远背景、墙体、地面、中景家具、角色/可互动物件、近景遮挡。
- 家具以统一视角预渲染或手绘，浏览器端按 Y 值排序。
- 近景可用一两块预先模糊的植物/栏杆/床脚形成景深，不依赖运行时 Gaussian blur。
- 地面保留足够留白，不做满屏复杂纹理；让仓鼠成为第一视觉焦点。

### 5.3 光影

只做低成本但感知价值高的部分：

- 椭圆接触阴影；
- 窗口暖光层；
- 全局昼夜色调 overlay；
- 少量高光粒子 / 尘埃；
- 家具下方预烘焙阴影；
- 必要时用 `globalCompositeOperation` 做轻量 screen/multiply 叠加。

不把 `CanvasRenderingContext2D.filter` 作为核心依赖，因为 MDN 当前仍标记它为 Limited availability。景深关键层优先直接输出模糊版本资源。

来源：https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/filter

### 5.4 像素与显示

- 推荐逻辑画布：480×270（16:9）。
- 角色关键 sprite 原生低分辨率绘制，再以整数优先的比例放大。
- 使用 `image-rendering: pixelated` 保留像素边缘；该属性已广泛可用。
- 对背景允许比角色更柔和，不要求所有元素都同等“硬像素”。这也是“软像素”的核心。

来源：https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/image-rendering

## 6. 资源格式与体量预算

WebP 继续作为主格式。MDN 当前说明 WebP 支持透明、动画，且无损 WebP 通常比同图 PNG 更小；主流浏览器已广泛支持。

来源：https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types

AVIF 可用于不要求像素级透明边缘的较大背景，但首轮不强制，因为 WebP 已足够稳定，且统一资产工具链更重要。

### 硬预算

- 首屏传输目标：≤ 1.5 MB
- 首屏硬上限：≤ 2.0 MB
- 全部 V3 核心视觉资源目标：≤ 3.0 MB
- 单个 sprite atlas 目标：≤ 400 KB
- 新运行时框架 gzip 目标：≤ 100 KB；优先 0 KB
- 手机目标：60 FPS；最低可接受：30 FPS

### 建议首屏分配

| 类别 | 目标预算 |
| --- | ---: |
| HTML/CSS/JS/状态机 | ≤ 100 KB raw 增量很小 |
| 仓鼠核心 atlas | 250~400 KB |
| 房间背景 + 深度层 | 450~650 KB |
| 可互动物件 atlas | 200~300 KB |
| 阴影/光斑/粒子/UI | 50~120 KB |
| 首屏合计 | 约 1.1~1.5 MB |

衣服、额外家具、季节主题、音频全部采用交互后或空闲时懒加载，不进入首屏硬预算。

## 7. 为什么这一版比当前 V2 更接近目标

当前 V2 的问题不是“Three.js 不够高级”，而是把资源预算投入到了运行时 3D 模型、vendor 和通用家具，却没有让角色轮廓、场景构图和统一美术语言达到目标。

V3 反过来：

1. 把 80% 的视觉预算放在角色和单房间画面本身；
2. 用预渲染/手绘把复杂的光影、材质提前烘焙进图片；
3. 浏览器只负责轻量合成和互动；
4. 用 Y-sort、遮挡、接触阴影和少量动态光产生“3D感”；
5. 固定镜头换取更高美术可控性和更小体量。

## 8. 下一阶段只做一个视觉切片，不做完整游戏

V3 第一原型应只有一个画面：

- 480×270 房间；
- 一只原创仓鼠；
- 食盆、床、滚轮各一个；
- 远景 / 地面 / 中景 / 近景至少四层；
- 仓鼠 idle + walk + eat 三个动作；
- Y-sort + 家具遮挡；
- 椭圆接触阴影；
- 一层暖光；
- 一层轻粒子；
- 桌面和 390px 手机都能显示。

不要接入正式存档，不做完整数值，不迁移正式入口。

### 原型通过条件

Art Director：
- 仓鼠第一眼必须比当前 V2 更可爱、轮廓更统一。
- 不能出现 Kenney 通用低模资产那种“拼素材包”观感。
- 场景必须有明显前中后层次，但仓鼠仍是视觉主体。
- 像素感应是设计语言，而不是简单把低分辨率图放大。

Technical Artist / QA：
- 原型首屏 ≤ 1.5 MB，硬上限 2.0 MB。
- 不加载 Three.js / GLB。
- 优先零新增运行时框架。
- 390px 手机无横向溢出。
- 普通桌面浏览器动画稳定；移动端目标 60 FPS，低端或节能状态不低于 30 FPS。
- 如果必须加入新框架，需先给出压缩后体积和不可替代收益，再决定。

## 9. 当前结论

V3 推荐路线不是“真正的 HD-2D”，而是：

**预渲染 / 手绘 2D 资产 + 固定斜俯视 + 分层深度 + Y-sort 遮挡 + 低成本动态光 + 低帧数角色动画的 Web Diorama 2.5D。**

内部视觉名称建议：**Soft Pixel Diorama（软像素玩具屋）**。

它吸收豆芝麻海豹的圆润玩具感和掌机养成氛围，吸收 HD-2D 的层次、光影、固定镜头和“2D角色存在于有深度的世界”这些原则，但避免把 3D 背景、GLB、Three.js 或重型引擎带进正式网页运行时。
